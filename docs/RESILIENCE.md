# 复杂使用场景与恢复策略（0.3.0）

| 场景 | 处理方式 |
| --- | --- |
| 没打开网易云、已退出、启动时还没有歌曲 | 显示等待，不发模型请求；打开并出现曲目后自动识别 |
| 连续快速切歌 | 重新等待稳定时间，取消上一首的评论请求；只为最终稳定曲目触发 |
| A→B→A 来回切换 | 通过状态代次识别过期请求，即使最后歌名相同也不复用旧任务 |
| 拖动进度 | 进度不属于歌曲身份；SMTC 检测到超过预期 5 秒的跳变，重新等待稳定时间 |
| 暂停、恢复 | 明确暂停时撤回未投递请求；恢复后重新等待；同首已请求过则不重复 |
| 单曲循环、重复打开同一首 | 不把回到开头当成换歌；最近已触发曲目 10 分钟内去重，最多记录 100 首 |
| 短暂丢失媒体信息、设备休眠后恢复 | 超过 10 秒的旧信息不可发言；恢复读取后重新稳定等待 |
| 系统时间被调回 | 重建稳定时间和节流记录，避免一直等到旧时钟时间 |
| 网易云有多个媒体会话 | 只选匹配应用，过滤 Closed，优先 Playing，按应用 ID 排序减少来源抖动 |
| SMTC 失败或系统服务重启 | 自动重新请求媒体管理器；可降级读取网易云窗口标题 |
| 窗口不是歌曲标题 | 窗口降级只接受含“歌名 - 歌手”式分隔符的标题，忽略通用应用标题 |
| 窗口标题格式变化或含多个分隔符 | 按正反顺序和多个片段解析，并去掉末尾的平台名；仍无法确认时按歌名匹配并标为未核实 |
| 歌曲搜索不匹配、评论为空、接口失败 | 先按歌手别名、括号版本后缀和基础歌名重试；仍失败则不编造评论，回退普通陪听，保留明确的匹配/失败说明 |
| 429、403、服务端错误 | 服务冷却 60 秒，已有正缓存仍可使用；负缓存避免重复请求 |
| 用户关闭评论或关闭播放器时正在获取评论 | 取消任务；撤回仍在宿主队列中的音乐数据与内部提示 |
| 事件投递失败 | 不提交曲目去重和两分钟冷却；撤回半套事件，30 秒后可重试 |
| 读取进程崩溃或卡死 | 20 秒无有效快照终止并重连；失败重试 2/4/8/16/32/60 秒，上限 60 秒 |
| 读取器输出异常或超长 | 拒绝无效快照，限制单行大小，超长时重启；不让旧状态继续触发 |
| World 反复启停 | start 幂等，stop 清时钟、取消请求、撤回积压并关闭读取进程；旧回调不能污染新实例 |
| 桌宠窗口未连接、没有发言工具、模型主动忽略要求 | 提示模型不要宣称已展示，也不无限重试；World 无权强制模型执行其他 World 的工具 |

## 可观察状态

World 页显示读取状态、当前曲目、陪听开关、评论区状态、本次已请求评论次数。评论区成功时显示实际条数。最后一项只计成功入队的请求，**不等于实际发言次数**。实际显示以 pet_say 回执和桌宠事件为准。

## 仍需明确的边界

- 歌词按歌名与歌手匹配，同名现场版可能拿到录音室歌词；官方翻译缺行或时间差超过 0.35 秒时不补齐，纯音乐或未收录曲返回 empty。歌词读取失败只影响歌词，不影响评论、歌曲背景和听歌记忆。
- 单曲循环计数依赖 SMTC 播放位置或曲目时长：有位置时按结尾回到开头计次；没有位置时按连续播放时间满一个时长计次。暂停不计，窗口标题降级（unknown）不计，手动拖动可能造成多计或漏计。
- 窗口标题降级没有播放进度和暂停信息，因此无法可靠区分暂停、拖动进度或静音；关闭「窗口标题降级」可选择只使用 SMTC。默认读取 `cloudmusic|QQMusic|qqmusic` 匹配进程，可用 `windowFallbackProcess` 调整。
- 歌名歌手不足以确定精确发行版本，检索匹配仍保留版本不确定性。
- 已经投递给模型或正在显示的气泡，World 无法撤回；模型收到提示后需要再检查当前状态，readyToComment=false 时跳过。
- 10 秒新鲜度、8 秒稳定等待、两分钟请求间隔，以及模型响应时间共同影响发言时机。大量快切时保持安静是预期行为。
- 网易云未文档化网页接口不能保证永久可用；本扩展不会绕过登录、验证码或访问限制。

## 验证范围

自动测试覆盖状态机、网络失败/限流、请求中途状态变化、旧任务隔离、队列撤回、读取器卡死重连、重复启停和异常输出；本机诊断验证当前网易云窗口读取。模拟测试不是对所有网易云版本、Windows 版本和模型的实机兼容保证。SMTC 拖动/暂停通过模拟快照验证，本机当前实际使用窗口标题降级。
