# 一起听

Coopanion 的非官方 Cortico World 扩展。读取本机音乐播放器的曲目信息，支持网易云与 QQ 音乐，在切歌稳定后给桌宠一次简短评论的机会。桌宠沿用现有的人格、模型和发言渠道。

1.8.0 把配置入口统一到 World 页的「设置」页签，移除标准配置页，避免同一套字段出现两份表单。设置页按「陪听与评论」「联网背景资料」「歌词」「一起听排名」「媒体读取」分组，用可展开/收回的折叠卡片展示，折叠时显示当前摘要，修改后由 World 自己校验并写入 `config.json`。媒体读取三项仍标注「重启 World」。

1.7.0 曾把标准配置页拆成五个分区，并新增折叠设置页；1.8.0 起标准配置页已移除。

1.6.0 新增歌词通道：曲目稳定后按当前曲目获取官方 LRC，切歌事件默认只带前 12 行（可调 3–80）与当前播放行；新增只读工具 `music_lyrics`，可取全文（最多 200 行）并带官方翻译、匹配不确定性和当前行。歌词里的制作名单行会被过滤；`hasTranslation=false` 时不生成译文；`match` 不确定时说明未核实；纯音乐或未收录曲返回 `empty`。歌词只作引用，公开场合最多引一两句；读取失败不影响评论、歌曲背景和听歌记忆。

1.5.0 增加单曲循环计数：同一首歌连续播放时不再只记一次。SMTC 提供播放位置时，检测到从结尾回到开头就再记一次；没有位置时（如网易云桌面版）读取曲目时长，连续播放每满一个时长加一次。暂停期间不计时，窗口标题降级（unknown）不计循环，手动拖动进度可能影响基于时长的估算。曲目时长优先来自 SMTC，缺失时通过一次在线搜索读取，因此需要开启「参考评论区（联网）」；关闭评论区时不估算循环。

1.4.1 明确配置页支持网易云音乐与 QQ 音乐；配置项和提示词中的「网易云评论区」「网易云百科」等标签统一改为「评论区」「歌曲百科」「歌手简介」，数据来源与隐私说明保留。

1.4.0 增加 QQ 音乐兼容：默认媒体会话匹配包含 `QQMusic|qqmusic`，窗口标题降级进程改为可配置正则 `windowFallbackProcess`，默认 `cloudmusic|QQMusic|qqmusic`。QQ 音乐需要在「设置 → 常规设置 → 通知」开启「显示系统媒体传输控件（SMTC）」，最新 Windows 版支持；开启后曲目识别、播放状态、听歌记忆和一起听排名可直接使用。评论、歌曲百科与歌手资料仍通过在线搜索，主流歌曲通常能匹配，QQ 音乐独家内容可能不可用并降级为普通陪听。旧配置在下次启用时会自动把默认网易云模式扩展为包含 QQ 音乐。

1.3.0 新增听歌记忆与「一起听排名」：曲目连续稳定 10 秒后，把歌名、歌手、专辑写入本机 `data/netease-companion/listening.json`，聚合出现次数、常听歌手与最近曲目。排名面板按播放次数列出常听歌曲与歌手；默认保留 100 首、30 位歌手，可在配置页调到 10–500 首、5–100 位；显示范围还可单独设为前 1–500 首、前 1–100 位，不影响实际收录上限。超过上限时，从旧记录中淘汰「歌曲播放次数 + 歌手出现次数」最低的一首，同分随机，刚播放的这首先保留；歌手同理。陪听事件和 `music_now_playing` 会附带一份紧凑的 `listeningMemory`，当前曲目或歌手以前听过时带 `relation`，方便桌宠自然联系；也可调用新增的 `music_listening_memory` 查看详情。它只是播放次数统计，不代表喜欢程度、评分或用户情绪，桌宠不会每首都翻旧账；快切或不足 10 秒的曲目不会计入。评论也可偶尔带一句轻松的听歌画像评价（例如播放《千恋万花》相关歌曲时说“原来你是柚子厨”），只在歌曲/厂牌/歌手资料或听歌记忆有明确指向时使用，用推测语气，不贴贬义或敏感标签，频率随互动画像变化，且不与提问同时出现。存储页签可单独清除「听歌记忆」。

1.2.0 新增陪听画像：用户明确说过的评论口味，以及「多说点 / 少说点 / 安静点」这类节奏要求，会写入本插件独立的 `preferences.json`。画像中的互动频率会自动缩短或放大主动评论间隔（more 0.75×、less 1.5×、quiet 4×，仍受 30–3600 秒边界约束），并相应调整互动提问频率；评论题材、详略和语气也会按画像调整。画像只在用户明确表达时学习，不从沉默、单次未回应或对歌曲本身的喜好推断；完全关闭主动评论仍由「允许切歌评论」开关控制。「实时状态」页会显示当前互动频率，存储页签可单独清除偏好与画像。

1.1.0 在百度百科歌曲词条之外接入网易云「歌曲百科」：随歌曲背景附带曲风、推荐标签、语种、BPM、获奖、影视节目、乐谱数、平台乐评、相似歌曲与相关歌单。歌曲百科按歌曲 ID 精确读取，匿名可用；百度百科继续提供创作背景和词曲/专辑/发行信息，两个来源各自标注，任一失败都不影响另一个。读取评论时，提到专辑、发行、词曲、获奖或影视等背景事实的评论会额外加权并优先保留。生成陪听评论时，优先讲创作背景和影视引用，其次才是专辑、发行、获奖或平台乐评；曲风、BPM、标签只有用户问起时才说。评论区只作听众视角补充；大约每 3–4 首加一次简短的互动问题或邀请，不强求每首都互动。顶部不会自动刷新的状态徽章已移除，状态统一看「实时状态」页签。

## 安装

需要 Windows 10 1809+ / Windows 11、网易云桌面客户端（也兼容开启 SMTC 的 QQ 音乐），以及支持 **World API 6** 的 Coopanion / Cortico。开发检查使用 Cortico 0.2.5；不能仅凭 Coopanion 的版本号判断接口兼容性。

扩展 1.8.0 已针对 **Coopanion 0.2.9**（World API 6）校验。新版「输入气泡」开关仅影响用户输入气泡，音乐评论仍使用桌宠 `pet_say` 输出。已有音乐配置、World ID 和工具名均保持兼容，不需重装或重建配置；旧配置缺少「评论参考条数」时按默认 10 条处理，缺少「联网搜索歌手背景资料」或「联网搜索歌曲背景资料」时按开启处理；旧版 `preferences.json` 只有评论口味、没有画像时按正常互动频率处理，不需要迁移文件。

发布到 npm 后，在 Coopanion 高级模式 → 扩展 → World 搜索 `better-cortico-world-netease-companion` 安装，然后重启进程，在 World 总览启用「一起听」。若搜索尚未收录，可在手动安装中输入完整包名。当前发布状态请以 npm registry 实际结果为准。

以下为源码本机安装方式：

1. 在本目录运行 `npm ci`，再运行 `npm run check`。
2. 打开 Coopanion 设置，进入高级模式 → 扩展 → World，选择「本机目录」。
3. 选择本项目所在目录（含 `package.json`）。若宿主拒绝中文路径，将源码放在英文路径目录后重试。
4. 安装后点击「重启进程」，在 World 总览启用「一起听」。
5. 播放网易云，切换一首歌，等待至少 8 秒。首次触发陪听，后续触发至少间隔 120 秒；扩展要求桌宠检查当前曲目、参考评论并调用 pet_say 展示简短气泡。模型响应和展示有额外延迟。

若安装器提示 API 不兼容，请先升级宿主或使用匹配宿主契约的扩展版本，不要直接把 manifest 的 api 改小。

`npm run diagnose` 会读取并输出约 10 秒的曲目信息，然后关闭读取进程，可以在安装前独立检查。它不会切歌或控制播放器。

## 工作方式

```text
网易云 → Windows SMTC / 网易云窗口标题 → 曲目稳定、去重和节流
           → World 外部事件 → 原有 Cormini 人格 → 桌宠原有发言渠道
```

- 默认每 2 秒读取一次；曲目稳定 8 秒后才提供评论机会。
- 曲目连续稳定 10 秒后写入本机听歌记忆，默认保留 100 首、30 位歌手（可调至 500/100）；快切不计入。
- 曲目稳定后可按需读取网易云官方 LRC 歌词：切歌事件默认只带前 12 行（可调 3–80）与当前播放行，需要全文时由桌宠调用 `music_lyrics`（最多 200 行）。
- 快速连切会合并，只关注当前最后一首；同一曲目不会反复触发。
- 在评论冷却期间继续更新状态；冷却结束后以当前曲目为准。
- SMTC 明确报告暂停时不触发评论，恢复播放后重新等待稳定时间。
- 可对桌宠说「先安静陪我听歌」「恢复切歌评论」，由 `music_set_commentary` 保存开关。也能在 World 配置中修改。
- 不添加第二套模型调用、不提供 TTS。事件唤醒现有模型仍会消耗其 token；两分钟间隔是机会间隔，不是保证的发言间隔。

## 能力边界

本扩展读取的是**曲目信息，不是音频**。不会将歌名当成实际听到了旋律、歌词或情绪的证据。不会修改 Persona、情绪、Memory 或 Coopanion 源码。

SMTC 可提供歌名、歌手、专辑和播放状态，但取决于网易云版本是否向 Windows 注册媒体会话。没有可用会话时默认降级为读取 `windowFallbackProcess` 匹配进程的非空窗口标题（默认 `cloudmusic|QQMusic|qqmusic`）。降级通道把整个窗口标题当作原始曲目标签，不猜测分隔符含义，播放状态标为 `unknown`：**不能可靠感知暂停、单曲循环、相同标题的不同录音，也可能受客户端窗口标题格式变化影响**。

如果只希望在确定正在播放时评论，请在 World 配置中关闭「窗口标题降级」。没有媒体会话时将保持安静。切歌到评论之间存在采样、模型响应和桌宠展示延迟，不会卡住播放器来制造静音间隙。

听歌记忆是出现次数统计，不是完整播放历史、播放时长或喜好评分；同一首歌循环播放只记一次连续收听，重启后仍保留。它默认保存 100 首曲目和 30 位歌手，可在「设置」页调整到最多 500 首/100 位；超过上限时按「歌曲播放次数 + 歌手出现次数」淘汰最低的旧记录，同分随机，刚播放的这首先保留。

近期曲目只在扩展进程内保留最近 20 条，重启清空；进入 Cortico 的事件和工具回执按宿主原本的日志策略保存。曲目信息、评论摘录及歌手资料会随模型请求发送到你配置的模型服务。启用评论参考或歌手资料后，歌名、歌手也会发送到 music.163.com 检索；歌手资料开启时，歌手名还会发送到 baike.baidu.com 与 api.discogs.com 查询公开简介；歌曲背景开启时，歌名会发送到 baike.baidu.com 查询歌曲词条，歌曲 ID 会发送到 interface.music.163.com 查询歌曲百科。本扩展不读取账号 Cookie、不上传音频；评论、歌手资料与背景摘录读取使用第三方网站未公开承诺稳定性的接口，并非官方开放平台服务，未来可能失效。只保留评论文本、点赞数、热门/最新分类，不收集评论者昵称或主页。歌手资料只保留简介、别名、作品名与专辑名，以及百科/社区页面的短摘录与链接。

陪听偏好与画像只保存在本机 `data/netease-companion/preferences.json`，内容是用户明确说过的评论口味（最多 50 条，含 sentiment、原话和可选标签）与互动频率画像（more/normal/less/quiet、用户原话依据、更新时间），不会写入人格记忆、会话记录或其他插件目录。只有用户明确表达喜好或节奏要求时，桌宠才会调用 `music_comment_preference` 记录；这份偏好与画像会随事件和 `music_now_playing` 提供给当前模型，因此也会进入模型请求。互动频率只影响本插件触发评论的间隔与提问频率，不影响其他 World 或普通聊天。World 页的存储页签「陪听偏好与画像」可以单独清除它。

听歌记忆只保存在本机 `data/netease-companion/listening.json`，内容是歌名、歌手、专辑、出现次数与最近收听时间（默认 100 首、30 位歌手，可调至最多 500 首/100 位）。它作为陪听事件的一部分进入模型请求，但不会上传到其他服务；不读取音频、不记录播放时长，也不收集账号信息。World 页存储页签的「听歌记忆」可以单独清除它，不影响偏好画像、人格或会话。

歌词读取的是网易云官方 LRC 文本，不是音频，也不代表桌宠听到了演唱。候选按歌名与歌手检索匹配，`match=title-artist-version-unverified` 表示只做到歌名歌手匹配、未核实发行版本，同名曲可能拿到别的录音的歌词；纯音乐或未收录曲返回 `empty`。官方翻译并非每首都有，`hasTranslation=false` 时不会生成译文；制作名单行（作词、作曲、编曲、和声编写等）会被过滤，不当作正文。歌词只以摘要形式随事件进入模型请求，本插件不把歌词写入磁盘、不缓存到本地文件。

## 配置

配置入口在 World 页的「设置」页签，按「陪听与评论」「联网背景资料」「歌词」「一起听排名」「媒体读取」分组折叠；折叠时显示摘要，修改后由 World 校验并写入部署 `config.json`。标准配置页不再提供这套字段。对应部署 `config.json` 的片段如下（合并进现有配置，不要覆盖整个文件）：

```json
{
  "worlds": {
    "netease-music": {
      "enabled": true,
      "commentary": true,
      "commentReference": true,
      "artistContext": true,
      "songContext": true,
      "lyricsContext": true,
      "lyricsTranslation": true,
      "lyricsLines": 12,
      "commentExcerpts": 10,
      "listeningTrackLimit": 100,
      "listeningArtistLimit": 30,
      "listeningRankTrackRange": 100,
      "listeningRankArtistRange": 30,
      "settleSeconds": 8,
      "cooldownSeconds": 120,
      "sessionPattern": "cloudmusic|netease|网易云|QQMusic|qqmusic",
      "windowFallback": true,
      "windowFallbackProcess": "cloudmusic|QQMusic|qqmusic"
    }
  }
}
```

`sessionPattern` 匹配 Windows 的媒体会话应用 ID，默认包含网易云与 QQ 音乐；`windowFallbackProcess` 匹配窗口标题降级要读取的进程名，两者都是正则，修改后重启 World。它们都不用于匹配歌曲内容。`windowFallback` 修改后也需重启。评论等待限制为 2–120 秒，间隔限制为 30–3600 秒，评论参考条数限制为 3–50，歌词行数限制为 3–80；听歌排名收录上限为 10–500 首、5–100 位歌手，显示范围为 1–500 首、1–100 位，均修改后热更新；显示范围超过收录上限时按收录上限显示。

## 更新与回退

**本机目录安装**：宿主以 link 方式加载这个目录，不从 npm 查询更新。保留目录位置，替换该目录的新版源码，运行 `npm ci`、`npm run typecheck`、`npm test`、`npm run describe`、`npm run check`，然后在 Coopanion 重启进程。配置由宿主保存在部署目录，包更新不覆盖它。

**npm 安装**：本分支发布名为 `better-cortico-world-netease-companion`（原名 `cortico-world-netease-companion` 归原作者所有，0.3.2 已发布，不能覆盖）。发布后扩展详情页会读取 `repository`、`homepage`、`bugs` 显示「源代码仓库 / 项目主页 / 问题反馈」，标签来自 `cortico.tags` 与官方索引；评分和评论由扩展市场提供。安装发布版后，用户可在宿主扩展页安装包名；扩展页检查新版本、更新并重启加载。旧版本可从扩展详情选择回退，前提是其 API 契约兼容。发布者操作见 [维护说明](docs/PUBLISH.md)。

使用公开 World 接口可减少宿主升级带来的影响，但不能保证未来破坏性契约变更无需适配。当前声明 `api: 6`，不兼容的宿主会由安装器拒绝。

## 开发与验证

```powershell
npm ci
npm run typecheck
npm test
npm run describe
npm run check
npm run diagnose
npm pack
```

`check` 使用 Cortico 自己的 manifest 解析器、dry-mount 和 describe 校验函数，验证构造、工具、配置归属与自描述一致性；它不启动桌宠或发送模型请求。`diagnose` 是本机音乐读取检查。完整桌宠发言效果仍需启用 World 后联调。
