# 听搭子

## 本项目原始作者：oceanxuhaiao

和[表达助手插件](https://github.com/oceanxuhaiao/coopanion-bubble-emotes)一起使用有奇效！Coopanion 的非官方 Cortico World 扩展。读取网易云音乐、QQ 音乐、酷狗音乐、酷我音乐与 Spotify 的当前曲目，优先通过 SMTC（系统媒体传输控件），必要时读取官方播放器的窗口标题；切歌稳定后让桌宠参考评论区、歌曲百科、歌手资料与歌词，主动发一条简短的陪听评论，并支持切歌报幕、同曲分段，随歌曲情绪使用形象已有的动作/表情。它还会记录本机听歌记录、听歌排名与个人画像，沿用桌宠现有的人格、模型和发言渠道。动作/表情只做提示，不新增动作或工具，形象不支持时只发言；也能在用户明确要求时暂停/切歌，或搜歌并给出链接。

## 安装

需要 Windows 10 1809+ / Windows 11、至少一款官方支持的桌面客户端（网易云音乐、QQ 音乐、酷狗音乐、酷我音乐或 Spotify），以及支持 **World API 6** 的 Coopanion / Cortico。开发检查使用 Cortico 0.2.5；不能仅凭 Coopanion 的版本号判断接口兼容性。

使用前请在音乐软件中开启 SMTC：QQ 音乐在「设置 → 常规设置 → 通知」勾选「显示系统媒体传输控件（SMTC）」；网易云音乐较新版本默认开启，若系统媒体卡片不显示，请更新到最新版并在设置中查找系统媒体/SMTC 相关选项；酷狗较新版本提供 SMTC，但通常没有播放进度；酷我建议保留「窗口标题降级」开启；Spotify 通常默认开启 SMTC。未开启时扩展读不到当前曲目。

扩展 1.15.1 已针对 **Coopanion 0.2.13**（World API 6）校验。新版「输入气泡」开关仅影响用户输入气泡，音乐评论仍使用桌宠 `pet_say` 输出。World ID 和工具名保持兼容，不需重装或重建配置；旧媒体读取正则会被替换为五款官方播放器的默认顺序，其余音乐配置继续沿用。旧配置缺少「评论参考条数」时按默认 10 条处理，缺少「联网搜索歌手背景资料」或「联网搜索歌曲背景资料」时按开启处理；旧版 `preferences.json` 只有评论口味、没有画像时按正常互动频率处理，不需要迁移文件。

发布到 npm 后，在 Coopanion 高级模式 → 扩展 → World 搜索 `better-cortico-world-netease-companion` 安装，然后重启进程，在 World 总览启用「听搭子」。若搜索尚未收录，可在手动安装中输入完整包名。当前发布状态请以 npm registry 实际结果为准。

以下为源码本机安装方式：

1. 在本目录运行 `npm ci`，再运行 `npm run check`。
2. 打开 Coopanion 设置，进入高级模式 → 扩展 → World，选择「本机目录」。
3. 选择本项目所在目录（含 `package.json`）。若宿主拒绝中文路径，将源码放在英文路径目录后重试。
4. 安装后点击「重启进程」，在 World 总览启用「听搭子」。
5. 播放网易云，切换一首歌，等待至少 8 秒。首次触发陪听，后续触发至少间隔 120 秒；扩展要求桌宠检查当前曲目、参考评论并调用 pet_say 展示简短气泡。模型响应和展示有额外延迟。

若安装器提示 API 不兼容，请先升级宿主或使用匹配宿主契约的扩展版本，不要直接把 manifest 的 api 改小。

`npm run diagnose` 会读取并输出约 10 秒的曲目信息，然后关闭读取进程，可以在安装前独立检查。它不会切歌或控制播放器。

## 工作方式

```text
官方播放器 → Windows SMTC / 播放器窗口标题（按优先级） → 曲目稳定、去重和节流
           → World 外部事件 → 原有 Cormini 人格 → 桌宠原有发言渠道
```

- 默认每 2 秒读取一次；曲目稳定 8 秒后才提供评论机会。
- 切歌报幕默认开启：先用半句自然带出歌名/歌手，再说感受；信息不确定时不硬报。
- 同曲分段默认关闭：开启后按设置 1–4 段；有 SMTC 位置时按播放比例，没有位置时按已播放时间间隔；有位置时事件带段落标签（按比例估）和当前段落附近的歌词窗口，没有位置时不带段落标签；仍受评论间隔与安静开关约束。
- 同一首歌的开场和后续分段会用 `commentFocus` 轮换侧重（创作背景、影视引用、专辑、歌手、歌词、评论、听歌记忆、用户画像、情绪/此刻），避免重复同一类事实或开头。
- 桌宠可按歌曲情绪使用当前形象已有的动作/表情；World 会读取宿主形象词表，只允许使用支持的词，并要求写进 `pet_say` 的【表情, 动作】括号；不会新增动作，形象不支持时只发言，听歌时不会用打盹/睡觉动作。可在设置中关闭「动作/表情提示」。
- 副歌段（`section.id=chorus`）会按公开曲风标签/BPM 估一个 `style`，并从当前形象词表里给动作建议；只用于选动作，不主动报曲风，仍最多一个动作。
- 用户明确说“记住这首/以后提醒我”时，桌宠可用 `music_note` 记一句（最多 120 字）；同曲事件会带 `songNote`，但只在自然时提。
- 桌宠可用 `music_tag` 给当前曲目标“烈/柔/旧/怪/淡”；之后同曲分段沿用，副歌动作优先用这个标签。
- 听歌排名与逐日历史在同一个 `listening.json`，不会按天数自动删除；顶部「个人画像」页按 7/30/90/全部汇总，切换窗口不会删数据。老版本没有逐日记录时，总播放、常听歌手、循环曲与曲风先用累计排名兜底，时段、每日与播放器图表随新播放补齐。
- 顶部「数据一览」只读列出本插件各数据文件的内容与磁盘大小（含合计），不提供清除按钮；只有听歌记录参与清理，偏好、口味快照、单曲笔记与听感标签都很小，保留即可。
- 顶部「数据清理」页可手动按 7/30/90/365/自定义保留天数清理：选择时预览会清理多少天、多少次播放，确认后只保留所选天数内的听歌记录（含今天），更早的逐日历史与对应累计排名删除，清理后小字提示实际清理量；只影响 `listening.json`，无法恢复。
- 听歌口味单独存 `taste.json`，只从听歌记录和明确偏好生成，不做人格定论；用户问“最近听了什么/什么时段听歌多”时可用 `music_history`/`music_taste`。
- 「常听曲风」从歌曲百科的曲风字段与手动听感标签汇总，列表最多八种，另用饼图展示前五；歌曲百科曲风会缓存到 `tags.json`，没有曲风数据的曲目不参与统计。
- 上一首已经评论过时，新歌开场可先用半句到一句收尾；不是单独的长篇总结。
- 播放器暂停/恢复/结束时，桌宠可回一句很短的状态提示；默认开启，60 秒最多一次，不会打断正在进行的评论。
- 曲目连续稳定 10 秒后写入本机听歌记忆，默认保留 100 首、30 位歌手（可调至 500/100）；快切不计入。
- 曲目稳定后可按需读取歌词：优先网易云官方 LRC，缺失时用 LRCLIB 同步歌词兜底；切歌事件默认只带前 12 行（可调 3–80）与当前播放行，需要全文时由桌宠调用 `music_lyrics`（最多 200 行）。
- 快速连切会合并，只关注当前最后一首；同一曲目不会反复触发。
- 在评论冷却期间继续更新状态；冷却结束后以当前曲目为准。
- SMTC 明确报告暂停时不触发普通陪听评论，但会发一句很短的状态提示（可在设置关闭）；恢复播放后重新等待稳定时间。
- World 页的「连接检查」可查看五款官方播放器是否安装、是否运行，以及 Windows 当前暴露的 SMTC 会话；会话表会标注「官方支持 / 未支持」，未连接时按软件给出开启路径与能力限制，点击「重新检测」刷新。
- 「读取诊断」页显示读取器收到的全部 SMTC 会话与窗口候选、最终选中的播放器、选择原因与粘性状态；可单独「重启读取器」，不用重启 World。多播放器同时打开时，当前播放器仍在播放会保持稳定，高优先级播放器需要连续出现约 4 秒才切换。
- 可对桌宠说「先安静陪我听歌」「恢复切歌评论」，由 `music_set_commentary` 保存开关。也能在 World 设置中修改。
- 播放控制默认关闭。开启后，只有用户明确说「暂停/继续/下一首/上一首」时，桌宠才会调用 `music_control`；不会主动控制播放。
- 桌宠可用 `music_pick` 搜索网易云/QQ 音乐并挑一首，但只能返回链接；扩展不能自动点播，需要用户自己打开。结果可能来自 QQ 音乐，后续评论/歌词仍按网易云数据匹配，独家内容可能降级。
- 不添加第二套模型调用、不提供 TTS。事件唤醒现有模型仍会消耗其 token；两分钟间隔是机会间隔，不是保证的发言间隔。

## 能力边界

本扩展读取的是**曲目信息，不是音频**。不会将歌名当成实际听到了旋律、歌词或情绪的证据。不会修改 Persona、情绪、Memory 或 Coopanion 源码。

SMTC 可提供歌名、歌手、专辑和播放状态，但取决于播放器版本是否向 Windows 注册媒体会话。没有可用会话时默认降级为读取播放器优先级列表里官方播放器进程的非空窗口标题（网易云音乐、QQ 音乐、酷狗音乐、酷我音乐、Spotify）。评论、百度百科与歌曲百科仍以网易云和公开百科为主；QQ 播放器会先用 QQ 公开搜索补充曲目标签，Spotify、酷狗、酷我没有公开评论/百科来源，匹配不到时只做普通陪听。降级通道把整个窗口标题当作原始曲目标签，不猜测分隔符含义，播放状态标为 `unknown`：**不能可靠感知暂停、单曲循环、相同标题的不同录音，也可能受客户端窗口标题格式变化影响**。酷狗即使走 SMTC 也通常没有播放位置与时长，酷我常退回窗口标题；这两种情况会在实时状态标注「无进度」，分段时间只是估算。

如果只希望在确定正在播放时评论，请在 World 配置中关闭「窗口标题降级」。没有媒体会话时将保持安静。切歌到评论之间存在采样、模型响应和桌宠展示延迟，不会卡住播放器来制造静音间隙。

播放控制只对 Windows 暴露的 SMTC 会话有效，能否暂停/切歌取决于播放器是否实现对应方法；失败会返回错误，不假装成功。`music_pick` 只做搜索和链接，不点播；两个客户端的公开外部点播通道都不可用。动作/表情只使用形象词表；宿主不认的词会被静默丢弃，因此词表读不到时只发言。

单曲笔记只保存用户明确说过的一句话，不是桌宠的推断；听感标签是反应方式，不是客观曲风；常听曲风依赖歌曲百科曲风字段和手动标签，可能不完整，多标签曲风会重复计入；听歌记录与听歌口味是播放次数、时段与播放器统计，不是播放时长、评分或情绪。原始逐日历史不按天数自动删除，需要时可在「数据清理」页按 7/30/90/365/自定义保留天数手动清理；个人画像页的 7/30/90/全部只是统计窗口，切换不会删数据。切歌收尾只在上一首已经评论过时给半句到一句，不是完整总结；播放器状态提示可能因正在进行的评论、60 秒冷却或曲目切换而跳过。

听歌记忆是出现次数统计，不是完整播放历史、播放时长或喜好评分；同一首歌循环播放只记一次连续收听，重启后仍保留。它默认保存 100 首曲目和 30 位歌手，可在「设置」页调整到最多 500 首/100 位；超过上限时按「歌曲播放次数 + 歌手出现次数」淘汰最低的旧记录，同分随机，刚播放的这首先保留。

近期曲目只在扩展进程内保留最近 20 条，重启清空；进入 Cortico 的事件和工具回执按宿主原本的日志策略保存。曲目信息、评论摘录及歌手资料会随模型请求发送到你配置的模型服务。启用评论参考或歌手资料后，歌名、歌手也会发送到 music.163.com 检索；歌手资料开启时，歌手名还会发送到 baike.baidu.com 与 api.discogs.com 查询公开简介；歌曲背景开启时，歌名会发送到 baike.baidu.com 查询歌曲词条，歌曲 ID 会发送到 interface.music.163.com 查询歌曲百科。歌词开启且网易云没有可用文本时，歌名、歌手会发送到 lrclib.net 查询公开同步歌词。使用 `music_pick` 时，搜索关键词会发送到 music.163.com 与 c.y.qq.com，只返回曲目与链接、不点播。动作/表情词表只读取本机宿主形象的 `figure.json`，不会上传；播放控制只在用户明确要求且设置允许时调用本机 SMTC 接口，不记录按键或播放历史。本扩展不读取账号 Cookie、不上传音频；评论、歌手资料与背景摘录读取使用第三方网站未公开承诺稳定性的接口，并非官方开放平台服务，未来可能失效。只保留评论文本、点赞数、热门/最新分类，不收集评论者昵称或主页。歌手资料只保留简介、别名、作品名与专辑名，以及百科/社区页面的短摘录与链接。

陪听偏好与画像只保存在本机 `data/netease-companion/preferences.json`，内容是用户明确说过的评论口味（最多 50 条，含 sentiment、原话和可选标签）与互动频率画像（more/normal/less/quiet、用户原话依据、更新时间），不会写入人格记忆、会话记录或其他插件目录。只有用户明确表达喜好或节奏要求时，桌宠才会调用 `music_comment_preference` 记录；这份偏好与画像会随事件和 `music_now_playing` 提供给当前模型，因此也会进入模型请求。互动频率只影响本插件触发评论的间隔与提问频率，不影响其他 World 或普通聊天。World 页的存储页签「陪听偏好与画像」可以单独清除它。

听歌记录（累计排名 + 逐日历史）只保存在本机 `data/netease-companion/listening.json`，累计部分保留歌名、歌手、专辑、出现次数与最近收听时间（默认 100 首、30 位歌手，可调至最多 500 首/100 位）。它作为陪听事件的一部分进入模型请求，但不会上传到其他服务；不读取音频、不记录播放时长，也不收集账号信息。World 页存储页签的「听歌记录（排名 + 历史）」可以单独清除它，不影响听歌口味、偏好画像、人格或会话。

单曲笔记只保存在本机 `data/netease-companion/notes.json`，每首最多一条、120 字；听感标签与歌曲百科曲风缓存在 `tags.json`，最多 500 首；听歌记录在 `listening.json`，同时保存累计排名与逐日历史（播放次数、歌手、时段与播放器，不记录播放时长），原始历史不按天数删除；听歌口味分析快照在 `taste.json`，由听歌记录与曲风缓存汇总生成。它们只作为事件或工具回执进入模型请求，不会上传到其他服务；World 页存储页签可分别清除「听歌记录（排名 + 历史）」「听歌口味」「单曲笔记」「听感与曲风标签」。

歌词优先读取网易云官方 LRC 文本，缺失时用 LRCLIB 的同步歌词兜底，不是音频，也不代表桌宠听到了演唱。候选按歌名与歌手检索匹配，`match=title-artist-version-unverified` 表示只做到歌名歌手匹配、未核实发行版本，同名曲可能拿到别的录音的歌词；纯音乐或未收录曲返回 `empty`。官方翻译并非每首都有，`hasTranslation=false` 时不会生成译文；制作名单行（作词、作曲、编曲、和声编写等）会被过滤，不当作正文。歌词只以摘要形式随事件进入模型请求，本插件不把歌词写入磁盘、不缓存到本地文件。

## 配置

配置入口在 World 页的「设置」页签，按「陪听与评论」「联网背景资料」「歌词」「听歌排名」「媒体读取」分组折叠；折叠时显示摘要，修改后由 World 校验并写入部署 `config.json`。标准配置页不再提供这套字段。对应部署 `config.json` 的片段如下（合并进现有配置，不要覆盖整个文件）：

```json
{
  "worlds": {
    "netease-music": {
      "enabled": true,
      "commentary": true,
      "announceTracks": true,
      "segmentComments": false,
      "segmentCount": 2,
      "segmentEverySeconds": 60,
      "actionHints": true,
      "allowPlaybackControl": false,
      "stateComments": true,
      "commentReference": true,
      "artistContext": true,
      "songContext": true,
      "lyricsContext": true,
      "lyricsTranslation": true,
      "lyricsLines": 12,
      "commentExcerpts": 10,
      "listeningTrackLimit": 100,
      "listeningArtistLimit": 30,
      "listeningRankTrackRange": 100,
      "listeningRankArtistRange": 30,
      "settleSeconds": 8,
      "cooldownSeconds": 120,
      "playerPriority": ["netease", "qq", "kugou", "kuwo", "spotify"],
      "windowFallback": true
    }
  }
}
```

`playerPriority` 是官方播放器的读取顺序，只允许 `netease`、`qq`、`kugou`、`kuwo`、`spotify`；设置页只提供上移/下移，不能增删或填入其他程序，修改后重启 World。`windowFallback` 决定 SMTC 不可用时是否读取官方播放器窗口标题，修改后也需重启。它们都不用于匹配歌曲内容。评论等待限制为 2–120 秒，间隔限制为 30–3600 秒，评论参考条数限制为 3–50，歌词行数限制为 3–80；分段次数为 1–4，无播放位置时的时间间隔为 0–300 秒；播放控制默认关闭，开启后只在用户明确要求时执行；状态提示默认开启；动作/表情提示可单独关闭。听歌排名与逐日历史在同一个 `listening.json`，不会自动按天数删除，可在「数据清理」页手动按保留天数清理；个人画像页只切换 7/30/90/全部统计窗口。听歌排名收录上限为 10–500 首、5–100 位歌手，显示范围为 1–500 首、1–100 位，均修改后热更新；显示范围超过收录上限时按收录上限显示。

## 更新与回退

**本机目录安装**：宿主以 link 方式加载这个目录，不从 npm 查询更新。保留目录位置，替换该目录的新版源码，运行 `npm ci`、`npm run typecheck`、`npm test`、`npm run describe`、`npm run check`，然后在 Coopanion 重启进程。配置由宿主保存在部署目录，包更新不覆盖它。

**npm 安装**：本分支发布名为 `better-cortico-world-netease-companion`（原名 `cortico-world-netease-companion` 归原作者所有，0.3.2 已发布，不能覆盖）。发布后扩展详情页会读取 `repository`、`homepage`、`bugs` 显示「源代码仓库 / 项目主页 / 问题反馈」，标签来自 `cortico.tags` 与官方索引；评分和评论由扩展市场提供。安装发布版后，用户可在宿主扩展页安装包名；扩展页检查新版本、更新并重启加载。旧版本可从扩展详情选择回退，前提是其 API 契约兼容。发布者操作见 [维护说明](docs/PUBLISH.md)。

使用公开 World 接口可减少宿主升级带来的影响，但不能保证未来破坏性契约变更无需适配。当前声明 `api: 6`，不兼容的宿主会由安装器拒绝。
