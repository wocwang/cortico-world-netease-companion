# 一起听 · 网易云音乐

Coopanion 的非官方 Cortico World 扩展。读取本机网易云音乐的曲目信息，在切歌稳定后给桌宠一次简短评论的机会。桌宠沿用现有的人格、模型和发言渠道。

1.0.0 是当前稳定版，汇总歌曲识别、最多 50 条评论筛选、歌手与歌曲背景、rising 高赞评论、实时状态页和独立陪听偏好记忆。

0.9.0 新增「联网搜索歌曲背景资料」开关并默认开启：随评论参考附带百度百科歌曲词条，补充创作背景、主题与风格，以及所属专辑、词曲、编曲、发行日期、原唱等字段。词条必须同时匹配歌名与歌手，同名歌曲不会串用背景；可在 World 配置页单独关闭。

0.8.0 新增评论筛选与偏好记忆：求赞、打卡、抢楼和只有一句泛泛夸奖的评论会被过滤，剩下的按信息量、点赞和新鲜度排序；最新评论里点赞最高的几条标为 `rising` 并加权。评论参考条数上限提高到 50（默认仍为 10）。桌宠可在用户明确表达喜好时，把评论口味写入本插件独立的 `data/netease-companion/preferences.json`，不和人格、会话或其他插件的记忆混在一起，并可在 World 存储页签单独清除。

0.7.0 新增「实时状态」页签：顶部徽章只在打开页面或手动刷新时取一次，这个页签在打开期间每 2 秒重新读取读取状态、当前曲目、评论区与歌手资料，不需要手动刷新。

0.6.0 给歌手资料补充第三方背景：默认同时查询百度百科概述与 Discogs 社区档案，和网易云简介并列，各自标注来源；词条需通过原名/别名校验，无关词条会被丢弃。整组请求最多等 5 秒，单个来源失败不影响其他来源。

0.5.0 新增「联网搜索歌手背景资料」开关并默认开启：除歌曲评论区外，陪听事件还会附带网易云歌手简介、别名、代表作品与专辑列表，帮助桌宠理解歌手平时的曲风与作品背景，而不只依赖网友评论。它和「参考网易云评论区」是两个独立开关，可随时在 World 配置页分别关闭。数据来自网易云公开歌手页接口，代表作品按热度排序并优先原专辑；结果缓存 24 小时。再次需要时也可让桌宠调用 `music_artist_context` 读取当前曲目的歌手资料。

0.4.0 扩大了歌曲识别范围：窗口标题按正反顺序解析，容忍歌手括号别名、合作歌手与 `(Live)`/伴奏等版本后缀；专辑不再作为硬性筛选条件，仅用于提高排序；检索取前 50 条，首次匹配失败时用基础歌名重试。评论参考默认从 5 条提高到 10 条，新增「评论参考条数」（3–20，默认 10，热更新），热门约占六成、其余为最新。

0.3.0 补充了未启动播放器、快切与来回切歌、拖动进度、暂停恢复、网络限流、读取器卡死及反复启停的防护。World 页可查看当前曲目与运行状态；详细行为及能力边界见 [复杂场景说明](docs/RESILIENCE.md)。

0.3.1 在配置页增加「评论最大字数」（默认 80，范围 10–500，含标点和外语字符）；「主动评论最短间隔」为 30–3600 秒，默认 120。两项热更新。间隔由扩展代码控制请求频率，字数通过当前状态工具、事件和环境提示词传给模型遵循；公共 World 接口不拦截其他 World 的 pet_say，因此字数不是输出层强制截断，也不影响普通聊天。

顶部六项是状态标签，不是会自动亮起的灯：读取状态、当前曲目、陪听开关、最近一次评论区获取状态、歌手资料获取状态、本次运行成功入队的评论请求次数。成功获取时「评论区」标签显示实际条数。请求次数不等于已展示气泡次数，重启清零。这些徽章由宿主在开页或显式刷新时取一次，不保证实时刷新；需要连续观察时打开「实时状态」页签，它每 2 秒自动更新。配置中的开启复选框是设置项，不代表播放器正在运行。

0.2.0 新增评论区参考：默认在评论机会到来时检索对应歌曲，并获取最多 10 条热门、最新评论的短摘录（0.2.0 时为 3 条热门 + 2 条最新；0.4.0 起可配置，每条最多 240 字），一同交给桌宠。桌宠参考网友感受，用自己的话回应，不逐条朗读。可在 World 配置页关闭「参考网易云评论区（联网）」。

匹配先按歌名与歌手核对，并容忍歌手括号别名（如「冯沁苑(买辣椒也用券)」）、合作歌手分隔符和 `(Live)`/伴奏等括号后缀；专辑一致只用于提高排序，不再作为硬性条件。窗口标题会按「歌名 - 歌手」及反向两种顺序解析，并去掉末尾的「网易云音乐」；没有分隔符时按歌名匹配。检索取前 50 条，首次匹配失败会用基础歌名重试。缺少歌曲 ID 或专辑一致时仍可能标记为 `title-artist-version-unverified`，不保证与当前录音的发行版本完全一致；不同版本的评论区可能不同。匹配失败、接口限流或超时就退回普通陪听，不编造网友观点。成功结果缓存 30 分钟，失败缓存 5 分钟，最多缓存 40 首；缓存键包含评论条数，修改条数后会重新获取。

## 安装

需要 Windows 10 1809+ / Windows 11、网易云音乐桌面客户端，以及支持 **World API 6** 的 Coopanion / Cortico。开发检查使用 Cortico 0.2.5；不能仅凭 Coopanion 的版本号判断接口兼容性。

扩展 1.0.0 已针对 **Coopanion 0.2.8**（World API 6）校验。新版「输入气泡」开关仅影响用户输入气泡，音乐评论仍使用桌宠 `pet_say` 输出。已有音乐配置、World ID 和工具名均保持兼容，不需重装或重建配置；旧配置缺少「评论参考条数」时按默认 10 条处理，缺少「联网搜索歌手背景资料」或「联网搜索歌曲背景资料」时按开启处理。

发布到 npm 后，在 Coopanion 高级模式 → 扩展 → World 搜索 `cortico-world-netease-companion` 安装，然后重启进程，在 World 总览启用「一起听 · 网易云音乐」。若搜索尚未收录，可在手动安装中输入完整包名。当前发布状态请以 npm registry 实际结果为准。

以下为源码本机安装方式：

1. 在本目录运行 `npm ci`，再运行 `npm run check`。
2. 打开 Coopanion 设置，进入高级模式 → 扩展 → World，选择「本机目录」。
3. 选择本项目所在目录（含 `package.json`）。若宿主拒绝中文路径，将源码放在英文路径目录后重试。
4. 安装后点击「重启进程」，在 World 总览启用「一起听 · 网易云音乐」。
5. 播放网易云音乐，切换一首歌，等待至少 8 秒。首次触发陪听，后续触发至少间隔 120 秒；扩展要求桌宠检查当前曲目、参考评论并调用 pet_say 展示简短气泡。模型响应和展示有额外延迟。

若安装器提示 API 不兼容，请先升级宿主或使用匹配宿主契约的扩展版本，不要直接把 manifest 的 api 改小。

`npm run diagnose` 会读取并输出约 10 秒的曲目信息，然后关闭读取进程，可以在安装前独立检查。它不会切歌或控制播放器。

## 工作方式

```text
网易云音乐 → Windows SMTC / 网易云窗口标题 → 曲目稳定、去重和节流
           → World 外部事件 → 原有 Cormini 人格 → 桌宠原有发言渠道
```

- 默认每 2 秒读取一次；曲目稳定 8 秒后才提供评论机会。
- 快速连切会合并，只关注当前最后一首；同一曲目不会反复触发。
- 在评论冷却期间继续更新状态；冷却结束后以当前曲目为准。
- SMTC 明确报告暂停时不触发评论，恢复播放后重新等待稳定时间。
- 可对桌宠说「先安静陪我听歌」「恢复切歌评论」，由 `music_set_commentary` 保存开关。也能在 World 配置中修改。
- 不添加第二套模型调用、不提供 TTS。事件唤醒现有模型仍会消耗其 token；两分钟间隔是机会间隔，不是保证的发言间隔。

## 能力边界

本扩展读取的是**曲目信息，不是音频**。不会将歌名当成实际听到了旋律、歌词或情绪的证据。不会修改 Persona、情绪、Memory 或 Coopanion 源码。

SMTC 可提供歌名、歌手、专辑和播放状态，但取决于网易云版本是否向 Windows 注册媒体会话。没有可用会话时默认降级为读取 `cloudmusic` 进程的非空窗口标题。降级通道把整个窗口标题当作原始曲目标签，不猜测分隔符含义，播放状态标为 `unknown`：**不能可靠感知暂停、单曲循环、相同标题的不同录音，也可能受客户端窗口标题格式变化影响**。

如果只希望在确定正在播放时评论，请在 World 配置中关闭「窗口标题降级」。没有媒体会话时将保持安静。切歌到评论之间存在采样、模型响应和桌宠展示延迟，不会卡住播放器来制造静音间隙。

近期曲目只在扩展进程内保留最近 20 条，重启清空；进入 Cortico 的事件和工具回执按宿主原本的日志策略保存。曲目信息、评论摘录及歌手资料会随模型请求发送到你配置的模型服务。启用评论参考或歌手资料后，歌名、歌手也会发送到 music.163.com 检索；歌手资料开启时，歌手名还会发送到 baike.baidu.com 与 api.discogs.com 查询公开简介；歌曲背景开启时，歌名会发送到 baike.baidu.com 查询歌曲词条。本扩展不读取账号 Cookie、不上传音频；评论、歌手资料与背景摘录读取使用第三方网站未公开承诺稳定性的接口，并非官方开放平台服务，未来可能失效。只保留评论文本、点赞数、热门/最新分类，不收集评论者昵称或主页。歌手资料只保留简介、别名、作品名与专辑名，以及百科/社区页面的短摘录与链接。

陪听偏好记忆只保存在本机 `data/netease-companion/preferences.json`，内容是用户明确说过的评论口味（最多 50 条，含 sentiment、原话和可选标签），不会写入人格记忆、会话记录或其他插件目录。只有用户明确表达喜好时桌宠才会调用 `music_comment_preference` 记录；这份偏好会随事件和 `music_now_playing` 提供给当前模型，因此也会进入模型请求。World 页的存储页签可以单独清除它。

## 配置

World 配置页提供热更新开关和节奏设置。对应部署 `config.json` 的片段如下（合并进现有配置，不要覆盖整个文件）：

```json
{
  "worlds": {
    "netease-music": {
      "enabled": true,
      "commentary": true,
      "commentReference": true,
      "artistContext": true,
      "songContext": true,
      "commentExcerpts": 10,
      "settleSeconds": 8,
      "cooldownSeconds": 120,
      "sessionPattern": "cloudmusic|netease|网易云",
      "windowFallback": true
    }
  }
}
```

`sessionPattern` 匹配 Windows 的媒体会话应用 ID，修改后重启 World。它不用于匹配歌曲内容。`windowFallback` 修改后也需重启。评论等待限制为 2–120 秒，间隔限制为 30–3600 秒，评论参考条数限制为 3–50。

## 更新与回退

**本机目录安装**：宿主以 link 方式加载这个目录，不从 npm 查询更新。保留目录位置，替换该目录的新版源码，运行 `npm ci`、`npm run typecheck`、`npm test`、`npm run describe`、`npm run check`，然后在 Coopanion 重启进程。配置由宿主保存在部署目录，包更新不覆盖它。

**npm 安装**：npm 上已有原作者发布的 0.3.2；本分支的 1.0.0 若以同一包名发布会被拒绝（包名归属原作者），需要换包名或由原作者添加维护者。发布到 npm 后，扩展详情页会读取 `repository`、`homepage`、`bugs` 显示「源代码仓库 / 项目主页 / 问题反馈」，标签来自 `cortico.tags` 与官方索引；评分和评论由扩展市场提供。安装发布版后，用户可在宿主扩展页安装包名；扩展页检查新版本、更新并重启加载。旧版本可从扩展详情选择回退，前提是其 API 契约兼容。发布者操作见 [维护说明](docs/PUBLISH.md)。

使用公开 World 接口可减少宿主升级带来的影响，但不能保证未来破坏性契约变更无需适配。当前声明 `api: 6`，不兼容的宿主会由安装器拒绝。

## 开发与验证

```powershell
npm ci
npm run typecheck
npm test
npm run describe
npm run check
npm run diagnose
npm pack
```

`check` 使用 Cortico 自己的 manifest 解析器、dry-mount 和 describe 校验函数，验证构造、工具、配置归属与自描述一致性；它不启动桌宠或发送模型请求。`diagnose` 是本机音乐读取检查。完整桌宠发言效果仍需启用 World 后联调。
